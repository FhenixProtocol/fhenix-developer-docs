---
title: "Gas per Operation"
description: "Measured gas of every FHE.sol operation, and how batching changes the cost"
---

Every value is measured on the deployed contracts (Ethereum Sepolia and Arbitrum Sepolia, September 2026; both chains return the same values) and rounded to the nearest 100 gas. For what the gas pays for, see [gas costs and benchmarks](/fhe-library/core-concepts/gas-and-benchmarks).

How to read the tables:

- **First call** is the price when the operation is the first FHE call in the transaction, which touches the TaskManager and ACL contracts cold. **Later calls** is the price of every additional FHE call in the same transaction.
- Each value is the highest across the supported types; the spread across types stays under 450 gas.
- `X` stands for the encrypted type: `asEuint32`, `asEbool`, `shareEuint64`, and so on. The seven encrypted types are `ebool`, `euint8` through `euint128`, and `eaddress`; "All" means all seven.

<Note>
Arbitrum charges an extra L1 data fee for transaction calldata. An FHE operation inside a contract adds no calldata, so it adds nothing to that fee. Encrypted inputs do add calldata.
</Note>

## Cast between encrypted types

| Operation | First call | Later calls | Types |
|---|---|---|---|
| Cast `asX(eY)`, target not `ebool` | 45,900 | 25,800 | Any to `euint8` to `euint128` |
| Cast to `ebool`, `asEbool(eY)` | 75,800 | 51,800 | Numeric types and `eaddress` to `ebool` |

A cast to `ebool` costs more because `FHE.sol` implements it as `ne(value, asX(0))`: two TaskManager tasks instead of one.

## Access control

All access-control operations support all seven types and cost the same for each. The two `is*` functions are `view`; they cost gas only when a contract calls them inside a transaction.

| Operation | First call | Later calls |
|---|---|---|
| `allow` | 44,700 | 28,700 |
| `allowThis` | 26,300 | 26,300 |
| `allowSender` | 44,700 | 28,700 |
| <code style={{ whiteSpace: "nowrap" }}>allowTransient</code> | 23,000 | 7,000 |
| `allowGlobal` | 44,100 | 28,100 |
| `allowPublic` | 44,100 | 28,100 |
| `isAllowed` | 22,200 | 6,200 |
| <code style={{ whiteSpace: "nowrap" }}>isPubliclyAllowed</code> | 21,900 | 5,900 |

`allowThis` shows one price because your contract calls it on a result it computed earlier in the same transaction, so the TaskManager is already warm. `isAllowed` is measured on a handle the account can access, which returns early; a denied check reads more storage and costs more.

## Decryption results

The four `verify*` and `get*` functions are `view`; they cost gas only when a contract calls them inside a transaction.

| Operation | First call | Later calls |
|---|---|---|
| <code style={{ whiteSpace: "nowrap" }}>publishDecryptResult</code> | 71,400 | 53,400 |
| <code style={{ whiteSpace: "nowrap" }}>verifyDecryptResult</code> | 15,100 | 6,100 |
| <code style={{ whiteSpace: "nowrap" }}>verifyDecryptResultSafe</code> | 15,700 | 6,700 |
| <code style={{ whiteSpace: "nowrap" }}>getDecryptResult</code> | 24,300 | 8,300 |
| <code style={{ whiteSpace: "nowrap" }}>getDecryptResultSafe</code> | 23,200 | 7,200 |

`publishDecryptResult` is measured with a non-zero result. A zero result, for example `false` or an amount of 0, leaves one storage slot at zero and costs less.

## Batching

One signature can cover many encrypted inputs, and one call can publish many decryption results. Inputs amortize well; published results do not, because each result writes its own storage.

Batch encrypted inputs, `asEuint32s` with one signature:

| Inputs in the batch | 1 | 2 | 4 | 8 |
|---|---|---|---|---|
| Total gas | 39,600 | 45,400 | 56,900 | 79,900 |
| Gas per input | 39,600 | 22,700 | 14,200 | 10,000 |
