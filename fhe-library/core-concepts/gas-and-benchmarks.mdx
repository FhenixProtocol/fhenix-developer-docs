An FHE operation splits its cost in two. Your contract pays gas onchain to request the operation. The encrypted math itself runs offchain in the [compute pipeline](/deep-dive/cofhe-components/compute-pipeline) and costs no gas.

## What the gas pays for

A call like `FHE.add` records a task through the TaskManager and returns a handle for the result. The gas covers that request and the access-control bookkeeping, not the FHE computation.

Two facts shape every number below:

- **The first FHE call in a transaction costs more.** It touches the TaskManager and ACL contracts cold. Every later FHE call in the same transaction finds them warm and costs about 20,000 gas less. The tables show both prices as **First call** and **Later calls**.
- **The encrypted type barely matters.** The FHE math runs offchain, so the request costs almost the same for `euint8` and `euint128`. Each value below is the highest across the supported types; the spread across types stays under 450 gas.

## How we measured

The numbers come from forks of the deployed contracts on Ethereum Sepolia and Arbitrum Sepolia, measured in September 2026. Each probe runs one `FHE` call in its own transaction and takes the `gasleft()` delta around the call. Values are rounded to the nearest 100 gas.

Both chains run the same contract code and return the same values, so one set of tables covers both.

<Note>
Arbitrum charges an extra L1 data fee for transaction calldata. An FHE operation inside a contract adds no calldata, so it adds nothing to that fee. Encrypted inputs do add calldata.
</Note>

| Operation | First call | Later calls | Types |

A cast to `ebool` costs more because `FHE.sol` implements it as `ne(value, asX(0))`: two TaskManager tasks instead of one.

### Access control

All access-control operations support all seven types and cost the same for each. The two `is*` functions are `view`; they cost gas only when a contract calls them inside a transaction.

| Operation | First call | Later calls |
|---|---|---|
| `allow` | 44,700 | 28,700 |
| `allowThis` | 26,300 | 26,300 |
| `allowSender` | 44,700 | 28,700 |
| <code style={{ whiteSpace: "nowrap" }}>allowTransient</code> | 23,000 | 7,000 |
| `allowGlobal` | 44,100 | 28,100 |
| `allowPublic` | 44,100 | 28,100 |
| `isAllowed` | 22,200 | 6,200 |
| <code style={{ whiteSpace: "nowrap" }}>isPubliclyAllowed</code> | 21,900 | 5,900 |

`allowThis` shows one price because your contract calls it on a result it computed earlier in the same transaction, so the TaskManager is already warm. `isAllowed` is measured on a handle the account can access, which returns early; a denied check reads more storage and costs more.

### Decryption results

The four `verify*` and `get*` functions are `view`; they cost gas only when a contract calls them inside a transaction.

| Operation | First call | Later calls |
|---|---|---|
| <code style={{ whiteSpace: "nowrap" }}>publishDecryptResult</code> | 71,400 | 53,400 |
| <code style={{ whiteSpace: "nowrap" }}>verifyDecryptResult</code> | 15,100 | 6,100 |
| <code style={{ whiteSpace: "nowrap" }}>verifyDecryptResultSafe</code> | 15,700 | 6,700 |

| <code style={{ whiteSpace: "nowrap" }}>getDecryptResultSafe</code> | 23,200 | 7,200 |

`publishDecryptResult` is measured with a non-zero result. A zero result, for example `false` or an amount of 0, leaves one storage slot at zero and costs less.

## What a confidential token transfer costs

Single operations do not tell you what a user pays. This table shows whole transactions on the reference [FHERC20](/fhe-library/confidential-contracts/fherc20/overview) token, with an encrypted input amount where the call takes one. The gas includes the 21,000 transaction base and the calldata.

| Action | Gas |
|---|---|
| `confidentialTransfer` to an existing holder | 421,500 |
| `confidentialTransfer` to a new holder | 474,400 |
| <code style={{ whiteSpace: "nowrap" }}>confidentialTransferFrom</code> by an operator | 424,800 |
| `setOperator`, a one-time approval | 46,700 |
| Baseline: plain ERC20 `transfer` to an existing holder | 34,500 |
| Baseline: plain ERC20 `transfer` to a new holder | 51,600 |

A transfer to a new holder pays for one extra FHE task, the encrypted zero it adds to, and for fresh storage slots. A plain ERC20 shows the same storage effect.

## How batching changes the cost

One signature can cover many encrypted inputs, and one call can publish many decryption results. Inputs amortize well; published results do not, because each result writes its own storage.

Batch encrypted inputs, `asEuint32s` with one signature:

| Inputs in the batch | 1 | 2 | 4 | 8 |
|---|---|---|---|---|
| Total gas | 39,600 | 45,400 | 56,900 | 79,900 |
| Gas per input | 39,600 | 22,700 | 14,200 | 10,000 |

Batch decryption results, `euint32`:

| Results in the batch | 1 | 2 | 4 | 8 |
|---|---|---|---|---|
| <code style={{ whiteSpace: "nowrap" }}>publishDecryptResultBatch</code> | 75,100 | 128,700 | 235,800 | 450,100 |
| <code style={{ whiteSpace: "nowrap" }}>verifyDecryptResultBatch</code> | 18,800 | 24,300 | 35,500 | 57,800 |
| <code style={{ whiteSpace: "nowrap" }}>verifyDecryptResultBatchSafe</code> | 19,500 | 25,400 | 37,100 | 60,700 |

## Performance benchmarks

The compute pipeline executes operations with [TFHE-rs](https://github.com/zama-ai/tfhe-rs), Zama's FHE library. For operation-level latency, use Zama's published numbers: [TFHE-rs benchmarks](https://docs.zama.ai/tfhe-rs/tfhe-rs/1.5/get-started/benchmarks).

Read them as the cost of the raw operation on reference hardware. End-to-end latency in CoFHE adds the steps around the operation: event pickup, validation, and commitment posting.
